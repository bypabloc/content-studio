# 031: «Enviar a» con cinco acciones y valores por defecto de cada pantalla

- **Contexto**: el Explorador tiene que encolar archivos sin abrir la app. El servidor no mapea acciones a trabajos: el inbox (spec 030) recibe `kind` y `params` libres.
- **Elegida**: el mapeo vive en el cliente (`SEND_JOB` en `client/src/app/external/useExternalRequests.ts`) con los valores que ya usa cada pantalla: convertir a MP3 → `media.convert` {`target: mp3`, `options: {}`}; normalizar → `media.normalize` {`preset: youtube`}; limpiar silencios → `clean.analyze` {modelo `large-v3-turbo`, idioma `es`, hueco 0,5 s, margen 0,15 s, bordes, `auto_render`}; transcribir → `transcribe` {modelo `large-v3-turbo`, idioma `auto`}; abrir en el Editor → el Editor con los archivos, sin trabajo. Los accesos directos los crea `CreateShortCut` en `$SENDTO` desde `client/src-tauri/installer/nsis/hooks.nsh` (instalación por usuario, sin admin), con `--send <acción>`.
- **Descartadas**: el menú moderno de Windows 11 (D-3, fuera de alcance); un mapeo en el servidor (una API nueva para cinco atajos); un inbox por acción (crearía carpetas).
- **Cómo revertir**: quitar los macros `NSIS_HOOK_POSTINSTALL` y los `Delete` de `$SENDTO` en `hooks.nsh`, la rama `--send` de `parseExternal.ts`, `SEND_JOB` y las claves `sendto.*`.
- **Cómo comprobarla**: `bun run --cwd client vitest run tests/unit/src/app/external` (valores por defecto, editor y el aviso con 2 encolados y 1 saltado). Con el instalador: `python -m devtools app-check run --binary=<exe> --scenario=031-sendto` (AC-6).
- **Verificado**: el instalador compila con `$SENDTO` y `${MAINBINARYNAME}`; tras instalar hay cinco accesos y al desinstalar no queda ninguno (`app-check`, `031-sendto`). Con la app abierta, `--send convert-mp3` con tres WAV encola tres trabajos (`031-send-jobs`).
